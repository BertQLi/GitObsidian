# Simple Git Sync 使用说明

## 仓库与安装

一个 vault 对应一个 GitHub 仓库，vault 根目录必须也是 Git 仓库根目录。

从 GitObsidian 的最新正式 Release 下载 main.js、manifest.json，放入 vault 的 `.obsidian/plugins/simple-git-sync/`，在第三方插件中启用。

- 第一台设备：填写空 GitHub 仓库地址、用户名和 PAT，点“初始化并首次同步”。
- 后续设备：克隆笔记仓库，把克隆目录作为 vault 打开，安装插件。插件读取 origin，本地 PAT 单独填写。

## 操作面板

```
Git 同步
仓库：已初始化
提交范围：整个 vault
上次成功：……

[立即同步]
保存本地改动 → 合并远程改动 → 上传

[提交范围…] [检查更新] v0.2.0
▸ 高级操作
▸ 详细信息
```

日常只使用“立即同步”。自动同步按设置的间隔执行相同过程，处理时主按钮禁用，状态栏显示当前阶段。

“高级操作”中的“仅上传”不下载，“仅下载”不创建本地提交，“同步整个 vault”只在本次忽略提交范围。

## 提交范围

默认整个 vault。需要把部分本地改动留到之后再提交时，点击“提交范围…”选择文件夹；清空选择恢复整个 vault。设置中的手动路径支持更具体的相对路径，与文件夹选择互斥，后一次配置生效。

范围仅限制本次提交。拉取、合并和推送按整个分支进行，已有提交也会一起推送。配置路径不存在时停止提交，不自动扩大范围。

## 冲突

发生合并冲突后，定时同步暂停。先在 Obsidian 中检查并解决冲突文件、完成合并，再手动同步以恢复自动同步；也可以在高级操作中取消未完成的合并。未解决冲突期间插件拒绝再次自动提交。

## 自动更新

设置中的“自动更新插件”默认开启，启动 30 秒后检查，成功检查至少间隔 24 小时；可以随时点“检查更新”。只接受 BertQLi/GitObsidian 的正式 Release。

校验所有文件后安装，保留 data.json。上一版代码保存在 `.update-backup/`。更新或重载失败时恢复旧版；宿主无法即时重载时，安装后提示重启 Obsidian。检查更新不使用笔记仓库 PAT。

本插件文件不通过笔记仓库分发，避免不同设备的同步覆盖自动更新。新设备只需首次安装，以后由更新器管理。

## 本地文件与配置

可共享的 `.obsidian` 配置及其他插件代码可随笔记同步。设备布局、缓存、插件 data.json、本插件目录和备份目录由本地规则排除。如果私有配置已经被 Git 跟踪，插件会停止并提示处理；忽略规则不会删除已发布的旧历史。

## 从源码安装

开发时在设置中把“插件源码目录”填为 GitObsidian/simple-git-sync 的绝对路径，再从高级操作选择“从本地源码安装”，按提示重载。

## 旧父仓库迁移

旧版“一个父仓库包含多个 vault”的布局需拆分。先备份仓库和本地设置，再为每个 vault 建独立仓库。有且只有一个 vault 时，也可将 Git 元数据迁入这个 vault，并新增一次根目录路径调整的提交；历史仍保留。其他设备需重新克隆或调整打开位置。
